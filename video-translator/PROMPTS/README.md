# 📮 حزمة أوامر الوكلاء

## نقطة البداية الحالية

للتنفيذ الفعلي استخدم [`01-CODEX.md`](01-CODEX.md) وحده كرسالة Codex الأولى.
هو أمر مكتفٍ بذاته، مشتق من `meta/COMMAND-OS.md`، ولا يحتاج إلى لصق وثيقة معمارية
كبيرة أو سجل المحادثة. يبدأ بـ **M0 فقط** ويضع ذاكرة التنفيذ على القرص.

القاعدة: لا ترسل لـ Codex «كمّل المشروع». أرسل رسالة فيها **هدف واحد قابل للاختبار**،
ثم اطلب exit code وآخر 30 سطراً من الخرج الخام. بعد قبول الهدف، أرسل حلقة جديدة
باستخدام القالب الموجود في نهاية `01-CODEX.md`.

## لماذا لا نلصق كل شيء؟

- `AGENTS.md` لا ينبغي أن يكون README معمارياً؛ اجعله صغيراً (≤150 سطراً).
- الاختبارات والكود هما المواصفة التي لا تعتمد على ذاكرة المحادثة.
- `ROADMAP.md` و`PROGRESS.md` هما ذاكرة العمل بين الحلقات.
- القيود الحرجة تُثبت باختبار أو hook/rule، لا بجملة قد تضيع عند ضغط السياق.
- Codex له حرية اختيار التنفيذ داخل حدود السلوك والقبول؛ القيادة ليست خنقاً له.

## بعد كل رسالة

لا تقبل عبارة «تم» وحدها. اطلب:

1. الحالة: `PASSING` أو `FAILING` أو `BLOCKED`.
2. أوامر التحقق الفعلية ورموز الخروج.
3. آخر 30 سطراً خاماً من كل أمر.
4. تحديث `ROADMAP.md` و`PROGRESS.md` بالدليل.

لا تُعلّم ميزة `passing` إذا بقي جزء منها `unverified`.
