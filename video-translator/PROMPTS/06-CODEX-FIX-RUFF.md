## OBJECTIVE — هدف واحد فقط

اجعل `ruff check .` يمر بنجاح في بيئة المشروع المحلية، مع الحفاظ على السلوك الحالي وكل الاختبارات، ومن دون تنفيذ أي هدف منتجي آخر.

## ما يجب فعله

1) سجّل baseline قبل التعديل:
   - `\.venv\Scripts\python.exe -m ruff check . --output-format=concise`
   - `\.venv\Scripts\python.exe -m pytest -q`
   - `\.venv\Scripts\python.exe tools\m0_smoke.py`
   استخدم الصيغة المناسبة إذا كان النظام POSIX، وسجّل الأمر الفعلي.
2) افحص قائمة Ruff كاملة، لا آخر 30 سطراً فقط. صنّف المخالفات إلى: إصلاح آمن، إصلاح يحتاج حكماً، ومخالفة كاذبة/غير مناسبة.
3) استخدم `ruff check --fix` فقط للإصلاحات الآمنة وبعد مراجعة diff. لا تستخدم `--unsafe-fixes` تلقائياً.
4) أصلح السبب في الكود. ممنوع إسكات 61 مخالفة بإضافة `# noqa` أو تعطيل قواعد Ruff في الإعدادات. استخدم استثناءً موضعياً فقط إذا كان السلوك المقصود مثبتاً باختبار وسجّلت السبب.
5) حافظ على semantics. مثال: `tools/self_audit.py` يعتمد على `subprocess.run` ويفحص `returncode`؛ إضافة `check=False` قد تكون إصلاح lint الصحيح، لكن لا تغيّر منطق اكتشاف فشل pytest إلى استثناء غير ملتقط.
6) لا تعدّل الاختبارات لتجاوز Ruff، ولا تعدّل `Segment` أو scheduler أو roofline أو mock pipeline إلا إذا أثبتت Ruff أن التعديل شكلي بحت ولا يغيّر السلوك.
7) تأكد أن `.venv/` لا يُضاف إلى git أو حزمة المصدر. إذا لم يوجد `.gitignore` أو لا يحتوي `.venv/`، أضف السطر الضروري فقط، وسجّله.
8) بعد الإصلاح شغّل بنفس مفسر البيئة:
   - `python -m ruff check .`
   - `python -m pytest -q`
   - `python tools/m0_smoke.py`

## حدود صلبة

- لا تثبّت PySide6 أو python-mpv الآن.
- لا تبدأ M1 ولا تغيّر بنية المنتج.
- لا تنزيل موديلات ولا اتصال وقت التشغيل.
- لا تحذف اختباراً ولا تضعفه ولا تغيّر acceptance لتناسب النتيجة.
- لا تعلّم M0 `passing`: واجهة UI ما زالت `unverified` في التقرير السابق.
- ثلاث دورات إصلاح/تحقق كحد أقصى. إذا بقيت مخالفة، توقف بحالة FAILING مع القائمة والدليل.

## القبول

الهدف ينجح فقط إذا:

1) `ruff check .` يعود بـ exit code 0.
2) `pytest` يعود بـ exit code 0، ولا يقل عدد الاختبارات عن baseline 94 دون تفسير.
3) `m0_smoke.py` يعود بـ exit code 0.
4) diff لا يحتوي تغييرات منتجية خارج إصلاح lint و`.gitignore` الضروري.
5) `ROADMAP.md` و`PROGRESS.md` محدثان، وM0 لا تزال غير مكتملة إذا بقي UI unverified.
