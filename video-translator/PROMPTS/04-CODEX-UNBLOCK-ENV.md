## OBJECTIVE — هدف واحد فقط

فك الحجب البيئي للتحقق من M0، بدون تغيير سلوك المنتج وبدون بدء هدف آخر.

## المطلوب

1) افحص هل يوجد `pyproject.toml` أو `requirements*.txt` أو بيئة محلية موجودة. لا تثبّت حزم تطوير في Python العالمي إذا كان يمكن استخدام بيئة المشروع.
2) أنشئ أو استخدم بيئة تطوير محلية للمستودع (`.venv` أو ما يعادلها حسب النظام). إذا لم يوجد ملف تبعيات تطوير، أضف ملفاً صغيراً يحتوي فقط على أدوات التحقق اللازمة: `pytest` و`ruff`، ولا تخمّن نسخاً بلا سبب. سجّل الإصدارات الفعلية.
3) ثبّت الأدوات في بيئة المشروع فقط. الاتصال بالإنترنت مسموح للتثبيت الصريح لهذه الأدوات فقط إن كانت البيئة/الموافقة تسمح؛ لا تنزيل موديلات، ولا PySide6/mpv في هذه الرسالة، ولا أي اتصال وقت التشغيل.
4) باستخدام **نفس مفسر Python** الذي ثبّتَّ فيه الأدوات، شغّل:
   - `python tools/m0_smoke.py`
   - `python -m pytest -q`
   - `python -m ruff check .`
   استخدم الصيغة الصحيحة للمفسر المحلي على Windows أو POSIX، وسجّل الأمر الفعلي لا الأمر النظري.
5) لا تعدّل `src/` أو الاختبارات لإخفاء فشل. إذا ظهر فشل برمجي بعد تثبيت الأدوات، أبلغ عنه كما هو؛ إصلاح الكود هدف لاحق.
6) حدّث `PROGRESS.md` بمفسر Python، إصدارات pytest/ruff، الأوامر الفعلية، exit codes، وما إذا كان الحجب البيئي زال. حدّث `ROADMAP.md` بالدليل فقط. لا تعلّم M0 `passing` إذا بقي اختبار UI اليدوي أو أي قبول آخر `unverified`.

## حدود صلبة

- لا تبدأ M1.
- لا تثبّت أو تنزّل موديلات.
- لا تضف PySide6 أو mpv الآن؛ عدم وجودهما معروف ومقصود أن يبقى خارج هذا الهدف.
- لا تغيّر سلوك mock pipeline أو `ImmutableCueError` أو النواة الحالية.
- إذا كان إنشاء البيئة أو التثبيت يحتاج موافقة أو شبكة غير متاحة، توقف بحالة BLOCKED ولا تستخدم نتيجة مزيفة.
- ثلاث محاولات إصلاح/إعادة تشغيل كحد أقصى، ثم توقف.
